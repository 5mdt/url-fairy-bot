# UFB-0033. App-generated static pages

**Tags:** #hosting #ops

## Behavior

Every HTML page the site serves (landing page, 404 page, per-file watch
pages) is generated by the app and written to disk in the cache directory.
The web server only serves files — it never renders anything, so the pages
Telegram and browsers see can never drift from what the app intends, and are
unit-testable Python instead of untestable server templating.

The Telegram Instant View example page is produced by the exact same
renderer as a real download's watch page, so it can never diverge from what
the bot actually sends.

## Implementation

- `app/pages.py` renders Jinja2 templates (`app/templates/`) and writes them
  atomically (write to a temp file, then rename) into `CACHE_DIR`.
- `write_watch_page(media_filename)` renders `<CACHE_DIR>/watch/<stem>.html`
  for a downloaded file; `attempt_download`
  (`app/url_processing.py`) calls it right after a download resolves,
  covering both a fresh download and a cache hit — so a watch page deleted
  independently of its media (or vice versa) repairs itself on the next
  request for that URL.
- `seed_static_pages()` creates `CACHE_DIR`, writes the landing page
  (`index.html`) and 404 page (`404.html`), copies the bundled
  `app/assets/preview.png` and `app/assets/sample.mp4` into the cache, and
  calls `write_watch_page("sample.mp4")` — producing the Instant View
  example page at `/watch/sample.html` via the real rendering path. Called
  once from the `app/main.py` lifespan on startup.
- The public URL for a watch page is `https://BASE_URL/watch/<stem>.html`
  (not `.../<stem>.mp4`), so the web server's extension-based MIME lookup
  serves it as `text/html` — the raw media keeps its own `.../<stem>.mp4`
  URL and `video/mp4` type unchanged.
- Nothing is left for the web server to configure: the shared cache volume
  is mounted directly at nginx's own default docroot; see
  [UFB-0030](UFB-0030-registry-only-deployment.md) for the image this runs
  on and the startup-ordering healthcheck this mount requires.

## Testing

### Unit

- `watch_page_path`/`watch_page_url` map a media filename to the right
  on-disk path and public URL, including percent-encoding.
- `render_watch_page` emits the full Instant View tag set with correctly
  substituted URLs, and escapes filename metacharacters.
- `write_watch_page` creates the `watch/` subdirectory when missing,
  overwrites an existing page, and leaves no leftover temp file.
- `seed_static_pages` writes the landing page, 404 page, both bundled
  assets, and the sample watch page; running it twice is idempotent.
- The seeded sample watch page is byte-identical to calling
  `render_watch_page("sample.mp4")` directly.

### Integration / Human

- `GET /` → the generated landing page.
- `GET /watch/<known file>.html` → `200 text/html` with the full meta tag
  set; `GET /watch/<unknown file>.html` → the generated 404.
- `GET /<file>.mp4` → unchanged, `200 video/mp4`.
- Sending a real URL to the bot still renders an inline-playable card in
  Telegram; a watch page exists on disk next to its media file.
- In the Instant View editor, `https://BASE_URL/watch/sample.html` renders a
  preview using the real per-file template.
