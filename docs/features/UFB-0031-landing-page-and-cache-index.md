# UFB-0031. Landing page

**Tags:** #ops #hosting

## Behavior

`BASE_URL`'s root serves a static landing page introducing the bot, instead
of a directory listing.

Cached files stay retrievable at their existing root-level path
(`https://BASE_URL/<file>`, see
[UFB-0025](UFB-0025-themed-download-file-server.md)).

There is no browsable index of the cache. Filenames embed the original
source URL they were downloaded from (see
[BUGS #14](../BUGS.md#14-cache-filenames-are-unbounded-and-directory-unsafe-medium-p2d2)),
and a listing would have exposed what URLs users have sent the bot; not
having one closes that off entirely rather than mitigating it.

## Implementation

- The landing page (`index.html`) is generated by the app at startup; see
  [UFB-0033](UFB-0033-static-page-generation.md).
- nginx serves the cache directory with no `autoindex` and no `/cache/`
  alias.

## Testing

### Integration

- Requesting `/` → the landing page, not a listing.
- Requesting `/cache/` → the generated 404 page.
- Requesting a cached file at its root-level path → served unchanged.
- Requesting an unknown path → the themed 404 page.
